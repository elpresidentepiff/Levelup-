# World 1 — Commands

| Mission | Child action | Primary evidence |
|---|---|---|
| Wake Byte | Build a short route | Sequence |
| Treasure Run | Order steps around required pickups | Sequence and goal planning |
| Predict Byte | Mentally execute a fixed route before Run | Prediction |
| Broken Bridge | Find and repair a collision | Debugging |
| Many Ways | Produce any valid solution | Flexible application |
| Shortest Route | Remove unnecessary movement | Efficiency and Lean thinking |
| Tell Byte | Build and explain why the route works | Explanation |
| Secret Bug | Detect a deliberately changed instruction | Debugging and verification |
| Build Your Maze | Create and save an original route | Creative application |
| Castle Boss | Transfer the skills without an initial hint | Independent mastery evidence |

Formal programming language appears after understanding. The World 2 reveal will name the repeated-action concept only after children feel the friction of issuing the same command many times.

Mission completion is not mastery by itself. The learner model records the capability, number of attempts, hint use and independent success. Later worlds should add retrieval and transfer challenges so confidence can rise or decay based on durable evidence.

## World 1 capability outcomes

| Capability | World 1 outcome | Evidence requirement |
|---|---|---|
| Sequencing | Mastery target | Independent evidence across at least four missions, including Castle Boss |
| Prediction | Mastery target | Independent evidence across all three prediction missions, including Castle Boss |
| Debugging | Mastery target | Independent evidence across all three debugging missions, including Castle Boss |
| Creative application | Mastery target | Independent evidence across all three creation/application missions, including Castle Boss |
| Efficient thinking | Introduced | One mission introduces the capability; mastery must be earned in a later world |
| Explanation | Introduced | One mission introduces the capability; mastery must be earned in a later world |

The app must never label an introduced-only capability as mastered in World 1. Conversely, every declared World 1 mastery target must remain reachable through genuine independent play; automated tests enforce both sides.

## Learning Engine V2 evidence

Every mission now declares its optimal program length and the skill, evidence dimension and context it can legitimately assess. Each run produces versioned structured evidence for the declared dimensions, including failures and recognised misconception patterns. Explanation choices produce separate explanation evidence.

The learner model derives per-skill summaries for recognise, predict, apply, debug, explain and transfer, plus independence, retention and confidence. These summaries are the foundation for the future adaptive engine. The current visible World 1 mastery labels continue to use the defended content-aware mission gates until Castle Boss V2 and non-grid transfer challenges provide enough evidence to switch those labels to the full multidimensional rules without making mastery unreachable.
